两条硬需求：

1. 文章页模板要能自定义
2. 写 Markdown，但中间要能插完整 HTML 且正常渲染

## 逐个框架

| |多文章模板 | md 内裸 HTML | 产物 |
|---|---|---|---|
| **Astro** | Layout 原生机制 | ✅ 默认透传 | 静态，0 JS |
| Hugo | Go template | ⚠️ 需开 `unsafe` | 静态，0 JS |
| Next.js | React 组件 | ✅ 走 MDX | 需配 `output: export` |
| VitePress | Vue 组件 | ✅ 走 Vue | 静态，0 JS |

## 决定性的一条

Hugo 的 Goldmark 默认 `unsafe = false`，裸 HTML 被静默吞掉。必须显式：

```toml
[markup.goldmark.renderer]
unsafe = true
```

不写的话文章里的 `<details>` 会**悄无声息地消失**，没有任何报错。这个坑踩过。

Astro 默认就透传，什么都不用配。

## 模板机制

Astro 的 Layout 不是插件，是 `.astro` 文件里一个 `<slot />`：

```astro
---
import PostLayout from './PostLayout.astro';
---
<PostLayout {...Astro.props}>
  <slot />
</PostLayout>
```

frontmatter 里 `layout:` 指哪个文件就用哪个。加新模板就是加一个文件，不用改站点结构。

对比 Next.js / VitePress：模板是 React / Vue 组件，文章本质变成「被 import 的组件」。对纯写作场景来说，写文章变成了写代码。

## 迁移成本

现有主页 2132 行、42KB CSS 的玻璃态设计 —— Astro 里 `<style>` 和 `<script>` 可以原样搬，不用重写。整个迁移就是「拆文件 + 换 news-item 那 8 行」。
